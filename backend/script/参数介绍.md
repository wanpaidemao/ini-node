# sugard(btcd)节点启动参数说明

本文档说明 `script/05-run.ps1` 中节点启动所用的参数及其作用。参数与上游
`btcd` 一致,其中 `--headerwindow`、`--windowlimit` 是本项目针对超长时间链
(hash history 时间线)与低内存运行场景设计的窗口可调参数。

## 启动参数一览

| 参数 | 示例 | 作用 |
| --- | --- | --- |
| `--datadir` | `--datadir=C:\Users\adest\AppData\Local\Btcd` | 数据目录,内含 `sugarmainnet/blocks_ffldb` 数据库 |
| `--rpcuser` | `--rpcuser=qYjMSzVGbXdgPJiuwxfMAp5EM3M=` | RPC 用户名(Basic auth) |
| `--rpcpass` | `--rpcpass=dSQjlIXRW7ETycroIhjlTqduT0A=` | RPC 密码 |
| `--rpclisten` | `--rpclisten=127.0.0.1:8334` | RPC 监听地址与端口 |
| `--debuglevel` | `--debuglevel=info` | 日志级别: trace/debug/info/warn/error/critical |
| `--headerwindow` | `--headerwindow=50000` | 内存中保留的区块索引高度窗口(核心参数) |
| `--windowlimit` | `--windowlimit=0` | 关闭窗口逐出,把所有区块全部缓存进内存 |

## 关键参数详解

### `--headerwindow`(窗口优化参数)

- 控制内存中 `blockIndex` 保留的区块头节点数量。
- 窗口**外**(更低高度)的节点会被 `evictWindow()` 从内存逐出,仅保留在
  DB 中;需要时通过冷读 `materializeColdNode` 从磁盘恢复。
- 设 `50000` = 内存只保留约 5 万个区块节点,面向极长链(高度可达数千万)
  的低内存运行。
- 设小值可以压内存,但频繁冷读会拖慢冷区块路径;设大值多占内存但冷读少。

### `--windowlimit`

- `--windowlimit=0` 表示不限制,把所有区块头部全部放进内存(全量缓存,
  不逐出)。
- 更适合做完整索引的诊断/一次性遍历;实测超过千万高度会占数十 GB 内存,
  一般运行建议先用 `--headerwindow`。

### `--datadir` 路径约定

- 本节点数据库不在常规 `data/` 子目录,而是直接位于:
  ```
  <datadir>\sugarmainnet\blocks_ffldb
  ```
- **必须显式带 `--datadir`**,否则默认路径找不到既有数据库。

## 冷启动 / 异常关机后的 UTXO 重建

- 若节点被强杀(如 `Stop-Process -Force`),下次启动时会从 DB 中最后一次
  UTXO 一致块开始,按高度逐块重放,直到追上最新区块。
- 窗口启用时,该一致块可能已被逐出内存;代码会通过冷读 + 高度索引直接
  从磁盘取块,不再依赖内存 parent 链,因此**窗口参数不会阻止恢复**。
- 重放耗时取决于「一致块高度 → tip 高度」的差值;差值越大恢复越久。
- 恢复完成后,运行 `script/04-sync-rate.ps1` 可观察同步速度。
