# 方案：btcd segwit 激活对齐（AlwaysActiveHeight 0→1）

> 制定日期：2026-08-17
> 目标：修复 SugarChain btcd fork 的 segwit 激活移植 bug，使 bech32（witness）交易可广播（对齐官方 umami 行为）。

---

## 一、背景与根因

### 问题
web-wallet 发送 bech32 交易报错：
```
broadcast: code -26: TX rejected: transaction ... has witness data, but segwit isn't active yet
```

### 根因链（已查证）
1. **官方（umami C++）**：`chainparams.cpp:90` `consensus.SegwitHeight = 0; // Always on`——**segwit 从创世（高度 0）就激活**，接受 witness 交易（sugar.wtf 钱包广播到 api-server 后端（umami）成功的原因）
2. **我们 btcd fork**：`sugar_params.go` `DeploymentSegwit.AlwaysActiveHeight: 0`——设计意图"创世激活"，但 btcd 的 `versionbits.go:261` **只对 nonzero AlwaysActiveHeight 生效**，`0` 被当作"未设置"→ segwit 走 BIP9 流程（状态 started）→ 未激活 → 拒绝 witness 交易
3. **定性**：这是**移植 bug**（配置值 0 语义未对齐），非链的共识限制

### 证据
- `getblockchaininfo`：segwit softfork 状态 = `started`（未激活）
- umami 源码：`SegwitHeight = 0`（Always on）
- api-server 后端接受 witness 广播（sugar.wtf 能发）

---

## 二、改动

```go
// chaincfg/sugar_params.go DeploymentSegwit
AlwaysActiveHeight: 0  →  AlwaysActiveHeight: 1
```

**原理**：btcd versionbits 对 `AlwaysActiveHeight > 0` 且 `nextHeight >= EffectiveAlwaysActiveHeight` 时强制激活。设 `1` = 从高度 1 起 segwit 强制激活（创世块本身无交易，等效"创世激活"），对齐 umami `SegwitHeight = 0` 的语义。

**影响范围**：仅 segwit 部署激活判定（`validate.go` 的 `enforceSegWit = segwitState == ThresholdActive` 变 true）→ btcd 接受 witness 交易（mempool 接收 + 校验）。

---

## 三、风险分析

| 风险 | 等级 | 说明/缓解 |
|------|------|----------|
| **链分叉** | 低 | 官方（umami）已激活 segwit → 修复是对齐行为；链上已同步 4390 万块无 witness 交易块（同步正常证明）→ 激活不影响已同步链 |
| **与其他未激活节点不一致** | 低-中 | 若存在基于我们 btcd fork 的其他节点（未修复）未来挖 witness 块，会拒绝——但主网挖矿多为 umami/Yumekawa（已激活或同规则），风险可控；建议实施后观察同步 |
| **mempool 接受更宽松** | 低 | 激活后 btcd 接受 witness 交易（这正是目标）；恶意 witness 交易仍走完整共识校验 |
| **回滚成本** | 低 | 改回 `0` 重编译重启即可 |

**关键确认**：官方就是创世激活 → **修复是修正 bug 而非单边共识变更**，分叉风险远低于"私自激活"。

## 七、实施结果（2026-08-17 实际执行，已批准）

- **P1 初改 `sugar_params.go`（SugarMainNetParams）→ 未生效**
- **关键发现（改错对象）**：运行时实际用 `chaincfg.MainNetParams`（`config.go` 的 `activeNetParams = &mainNetParams` → `Params: &chaincfg.MainNetParams`），`SugarMainNetParams`（sugar_params.go）**不是运行时对象** → 初改无效
- **单测定位**：`TestSegwitForceActive`（blockchain/segwit_active_test.go）→ `AlwaysActiveHeight=1 → ForceActive=true`（配置值本身正确）
- **最终修正**：`chaincfg/params.go` 的 `MainNetParams.DeploymentSegwit.AlwaysActiveHeight: 0→1`（运行时对象）；`sugar_params.go` 回滚（改回 0）
- **决定性验证**：广播构造的 witness 交易（decoderawtransaction 通过）
  - 修复前：`-26 has witness data, but segwit isn't active yet`
  - 修复后：`-25 orphan transaction references outputs of unknown...`（prevout 为测试用假 hash → 孤儿拒绝，非 witness 问题）→ **segwit 已激活**
- **实测**：web-wallet 发送 bech32 交易成功（`Sent ✓ 9ad7feb1...`，即之前被 -26 拒绝的同一笔）
