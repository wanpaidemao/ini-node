# 前后端整合方案：单入口运行（前端自动托管后端节点）

> 制定日期：2026-08-15
> 现状：前端（Wails 桌面应用 `frontend/bin/ini-node.exe`）与后端（btcd 节点 `backend/btcd.exe`）分离，需分别启动（前端走 `wails dev`/`ini-node.exe`，后端走 schtasks `btcd-node` 或 `script/05-run.ps1`）。
> 目标：**只打开前端一个入口**，由前端自动拉起/托管后端节点，退出时自动清理。

---

## 一、现状盘点（已确认）

| 项 | 现状 |
|----|------|
| 前端 | Wails 应用，`rpcproxy.go` 的 `rpcProxyMiddleware` 代理 `/rpc → 127.0.0.1:8334`；已有 `/api/node-config`、`/api/index-progress` 端点 |
| 前端已能解析 ini | `findIniPath()` + `parseIni()` 已从 `btcd-runtime.ini` 读 rpcuser/rpcpass/rpclisten/datadir |
| 后端 | `backend/btcd.exe --configfile=btcd-runtime.ini --sugarindex=1`（schtasks `btcd-node` 或 `script/05-run.ps1`） |
| 数据目录 | `%AppData%/Local/Btcd/sugarmainnet/`（index/ 已含 progress.json） |
| 互斥 | 重建与同步不会同时进行；`/api/index-progress` 已打通前端显示 |

## 二、方案对比

### 方案 A：前端自动拉起后端子进程（推荐，改动最小）

前端（Wails `main.go`/`app.go`）在启动时检测 `127.0.0.1:8334` 是否可连：
- **不可连** → `exec.Command` 拉起 `backend/btcd.exe --configfile=<ini> --sugarindex=1`，stdout/stderr 重定向到 `backend/logs/`，保存子进程句柄
- **可连**（已有节点在跑）→ 不拉起，直接复用
- 前端退出（Wails `OnShutdown`）→ kill 子进程（仅当是本进程拉起的）

| 项 | 说明 |
|----|------|
| 改动文件 | `frontend/main.go`（或新增 `backendhost.go`） |
| 优点 | 单入口=前端；后端生命周期由前端托管；逻辑简单 |
| 缺点 | 需定位 btcd.exe 路径（默认 `..\backend\btcd.exe`，可配置） |
| 风险 | 低 |

### 方案 B：后端内嵌前端（单二进制，改动大）

把前端 `dist/` 用 `go:embed` 打进 btcd，访问 `http://127.0.0.1:8334/` 直接出 UI。

| 项 | 说明 |
|----|------|
| 优点 | 真正单二进制，无子进程管理 |
| 缺点 | btcd RPC 是 JSON-RPC POST，服务网页需新增 HTTP handler 与前端构建链路；改动大、风险高 |
| 风险 | 高（不建议首期） |

### 方案 C：前端 + 节点打包成整体（安装包/托盘）

用 Wails + NSIS/Wix 打包，前端作为主程序托管节点子进程（同方案 A 的托管逻辑），并处理开机自启/托盘。属于方案 A 的发布形态。

### 推荐

**方案 A**（前端自动拉起/托管后端子进程）——改动最小、单入口达成，后续可平滑升级到方案 C。

## 三、方案 A 详细设计

### 3.1 新增 `frontend/backendhost.go`

```go
// BackendHost 管理 btcd 子进程生命周期。
type BackendHost struct {
    cmd    *exec.Cmd
    ini    string   // btcd-runtime.ini 路径
    exe    string   // btcd.exe 路径
    started bool
}

// EnsureRunning: 探测 8334;不可连则拉起 btcd 子进程。
func (h *BackendHost) EnsureRunning() error

// Shutdown: 前端退出时 kill 自己拉起的子进程。
func (h *BackendHost) Shutdown()
```

关键逻辑：
1. `probeRPC()`：`http.Get("http://127.0.0.1:8334/")` 或尝试 `/api/index-progress` 同端口，可连则跳过
2. 定位 exe：优先 `frontend/../backend/btcd.exe`，其次 `backend/` 同级、或环境变量 `BTCD_EXE`
3. 拉起：`exec.Command(exe, "--configfile="+ini, "--sugarindex=1")`，`Stdout/Stderr` 重定向到 `backend/logs/node.stdout.log` / `node.stderr.log`（追加）
4. `OnShutdown` 钩子：若 `h.started` 则 `cmd.Process.Kill()` + `cmd.Wait()`
5. 端口探测失败重试：启动后每 2s 探测 8334，最多 60s（兼容 8-10 分钟索引加载前的等待——实际 RPC 在重建完成后才监听，此时 `/api/index-progress` 已能给前端显示进度，前端不阻塞）

### 3.2 Wails 接入（`frontend/main.go`）

```go
host := &backendhost.BackendHost{Ini: findIniPath(), Exe: defaultBtcdExe()}
// 在 Wails options 前确保节点拉起:
if err := host.EnsureRunning(); err != nil { log.Println("backend start:", err) }

wails.Run(&options.App{
    OnStartup:  app.startup,
    OnShutdown: func(ctx context.Context) { host.Shutdown() },
    Middleware: rpcProxyMiddleware(),
    // ...
})
```

### 3.3 配置来源

- ini 路径：复用现有 `findIniPath()`（`%AppData%/Local/Btcd/btcd-runtime.ini` 或 `backend/btcd-runtime.ini`）
- exe 路径：默认 `..\backend\btcd.exe`（相对前端 exe），支持环境变量 `BTCD_EXE` 覆盖

### 3.4 前端无阻塞

- 后端刚拉起时 RPC 未监听（重建中），前端照常启动，`/api/index-progress` 显示重建进度（已实现）
- 无需等待 8334 就绪；`getSyncStatus` 失败时前端自动降级为索引进度显示

## 五、风险与注意事项

- 子进程句柄泄漏：必须 OnShutdown 清理；`cmd.Wait()` 防僵尸
- 重复拉起：探测端口先行，避免多实例
- 日志：子进程输出进 `backend/logs/`，与 schtasks 方式一致
- 若用户仍想独立跑后端（schtasks），探测到 8334 已监听则前端不拉起——两种方式兼容

## 六、后端配置管理（btcd 怎么配置）

方案 A 中前端以 `--configfile=btcd-runtime.ini` 拉起 btcd，**后端配置 = 编辑 ini 文件**。前端通过现有 `/api/node-config`（`rpcproxy.go` 的 `handleNodeConfig`）读写，扩展支持全部键：

| 配置项 | ini 键 | 前端控件 | 默认值 | 说明 |
|--------|--------|----------|--------|------|
| 数据目录 | `datadir` | 文本框 | `%AppData%/Local/Btcd` | 节点数据/索引存放位置 |
| RPC 监听 | `rpclisten` | 文本框 | `127.0.0.1:8334` | host:port |
| RPC 用户 | `rpcuser` | 文本框 | `sugar` | Basic Auth 用户名 |
| RPC 密码 | `rpcpass` | 密码框 | `sugar` | Basic Auth 密码 |
| 明文连接 | `notls` | 复选框 | `1` | 1=HTTP 直连（当前无证书） |
| 头部窗口 | `headerwindow` | 数字框 | `50000` | 内存头部窗口（与挖矿难度保护相关，勿乱改） |
| UPnP | `upnp` | 复选框 | `1` | 端口映射 |
| 地址索引 | `sugarindex` | 复选框（修改提示） | `1` | 首次开启触发全量重建（约 4-8h） |
| Profile 端口 | `profile` | 数字框 | `6000` | pprof 调试端口 |

### 保存与生效流程

1. **读取**：前端启动/进入设置页 → `GET /api/node-config` 返回全部 ini 键值（现有端点需扩展返回 datadir/headerwindow/upnp/sugarindex/profile/notls）
2. **编辑**：Settings 页表单绑定各键
3. **保存**：`POST /api/node-config` 全量写回 ini（`writeIni` 已支持逐键更新）
4. **生效**：提示「保存成功，重启节点后生效」→ 用户点「重启节点」按钮 → 前端 Go 方法：`host.Shutdown()` + `host.EnsureRunning()`（自动用新 ini 重启 btcd）

> 注意：`datadir`/`sugarindex` 变更会导致索引重建或位置变化，保存时明确提示。

## 七、前端「后端设置」菜单设计

### 入口与布局

- 位置：`Settings.svelte` 新增 **「后端 / Backend」区块**（放在现有 configuration 区块之后）
- 卡片结构：`node 状态条`（运行中 / 索引重建中 X% / 已停止）+ 配置表单 + 操作按钮

```
┌─ Backend ──────────────────────────────────────────────┐
│  ● 运行中  (PID 34900 · 索引重建中 60%)                  │
│                                                        │
│  数据目录     [ C:\...\AppData\Local\Btcd        ]      │
│  RPC 监听     [ 127.0.0.1:8334                    ]      │
│  RPC 用户     [ sugar                            ]      │
│  RPC 密码     [ •••••                            ]      │
│  ☑ 明文连接(notls)   ☑ UPnP                         │
│  头部窗口     [ 50000 ]   Profile 端口 [ 6000 ]        │
│  ☑ 地址索引 sugarindex（修改需全量重建）                 │
│                                                        │
│  [ 保存 ]  [ 重启节点 ]   ↳ 提示: 保存后重启生效          │
└────────────────────────────────────────────────────────┘
```

### 状态条逻辑

| 状态 | 判定 | 显示 |
|------|------|------|
| 运行中（同步/就绪） | `getSyncStatus` 成功 | 绿点 · 运行中 · 高度/目标 |
| 索引重建中 | RPC 失败 + `/api/index-progress` 有值 | 黄点 · 索引重建中 X% |
| 已停止 | 两者都无 | 灰点 · 已停止 + 「启动节点」按钮 |

### 新增/改动点

| 文件 | 改动 |
|------|------|
| `rpcproxy.go` `handleNodeConfig` | GET 返回全部键（datadir/headerwindow/upnp/sugarindex/profile/notls）；POST 全量写回 |
| `Settings.svelte` | 新增「后端」区块表单 + 状态条 + 保存/重启按钮 |
| `services.ts` | `getNodeConfig()`/`saveNodeConfig()` 扩展字段；新增 `restartNode()`（绑定前端 Go 方法） |
| `backendhost.go` | 导出 `Restart()`（Shutdown + EnsureRunning），供 Wails 绑定 |
| `main.go` | Wails `Bind` 暴露 `BackendHost.Restart` 给前端 |

### 交互细节

- **重启节点**：点击后 `host.Shutdown()` → 前端 Go 方法返回 → `host.EnsureRunning()` 用新 ini 拉起 → 前端自动回到「索引重建中/运行中」状态
- **保存**：仅写 ini 不重启（用户自选时机重启）；保存后按钮置灰「已保存，需重启生效」
- **错误提示**：`rpcpass` 为空或 `rpclisten` 非法时前端校验并拒绝保存
