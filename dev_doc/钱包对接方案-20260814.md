# 钱包对接方案：ini-node（btcd）为 web-wallet 提供钱包能力

> 制定日期：2026-08-14
> 涉及项目：
> - ini-node（btcd 全节点）: `sugarchain-node/backend`
> - web-wallet（Wails 桌面钱包）: `web-wallet/sugar-wallet`

---

## 一、结论速览

| 问题 | 结论 |
|------|------|
| btcd 能否直接当钱包？ | **不能**。`rpcAskWallet` 中的 `getnewaddress/importprivkey/dumpprivkey/sendtoaddress` 等全部为占位（提示连接 btcwallet）；btcd 无内置钱包/私钥管理 |
| web-wallet 需要 btcd 提供什么？ | 仅**链上查询与广播**：余额 / UTXO / 手续费 / 交易 / 广播（签名由 web-wallet 本地完成） |
| 是否可直接用 rpcclient？ | **可以**。btcd 的 sugarindex 扩展已提供对应 RPC，web-wallet 用 `btcd/rpcclient` 直连即可；需补依赖 + 字段适配 |
| 最佳落地方式 | **方案 A：web-wallet 改用 rpcclient 直连**（推荐）；方案 B：ini-node 侧加薄 REST 网关 |

---

## 二、现状核对（已核查代码）

### 2.1 btcd 侧（ini-node backend）

- **无内置钱包**：`rpcserver.go` 的 `rpcAskWallet` 列表（约 40 个钱包方法）全部为占位，调用返回"请连接 btcwallet"类错误
- **sugarindex 扩展已具备链上查询**（`rpcserver.go:193-199` 注册）：

| RPC 方法 | 功能 | 返回结构（`btcjson/sugarindexcmds.go`） |
|----------|------|-----------------------------------------|
| `getaddressbalance` | 地址余额 | `{balance, balance_immature, balance_spendable, received}` |
| `getaddressesbalance` | 多地址余额 | 同上数组 |
| `getaddressutxos` | 地址 UTXO | `{address, txid, outputIndex, script, satoshis, height}` |
| `getaddressdeltas` | 地址收支明细 | `{satoshis, txid, index, height, address}` |
| `getaddresstxids` | 地址交易列表 | `[]txid` |
| `getaddressmempool` | 内存池交易 | 待确认交易 |
| `getblockhashes` | 块哈希 | — |
| 核心 RPC | `estimatefee` / `getrawtransaction` / `sendrawtransaction` | 标准 |

### 2.2 web-wallet 侧（sugar-wallet）

- **自管私钥**：`internal/wallet/key.go` — `btcec.PrivateKey`，支持随机生成 / WIF 导入 / Legacy KDF 导入（`kdf.go` 52 轮 SHA-256 复刻原钱包）
- **自管签名**：`internal/tx/tx.go` `BuildAndSign` — 本地 `txscript` 签名、序列化 hex，**不调用** `signrawtransaction`
- **自管地址**：`internal/address/address.go` `DeriveAll`（bech32/segwit/legacy）
- **当前网络层**：`internal/api/sugar.go` 是 **REST 客户端**（`GET /balance/{addr}`、`/unspent/{addr}`、`/fee`、`/transaction/{hash}`、`POST /broadcast`），**无认证头**；`go.mod` **无 `rpcclient` 依赖**（仅有 btcd v0.24.2 主依赖）
- **默认端点**：`https://api.sugar.wtf`（主链 REST）、`https://tokenstest.sugar.wtf`（代币层，btcd 无法替代）

## 三、rpcclient 直连可行性评估（重点）

### 3.1 认证

- web-wallet 现 REST 客户端无认证；rpcclient 通过 `ConnConfig{User, Pass, Host}` 内建 **Basic Auth**，直连 `btcd-runtime.ini`（`rpcuser=sugar/rpcpass=sugar/rpclisten=127.0.0.1:8334`）✅

### 3.2 方法映射（web-wallet REST → btcd RPC）

| web-wallet 当前 | btcd RPC | 匹配 |
|-----------------|----------|------|
| `GET /balance/{addr}` | `getaddressbalance` | ✅ 字段：`balance_spendable`→confirmed，`balance_immature`→unconfirmed |
| `GET /unspent/{addr}?amount=N` | `getaddressutxos` | ✅ 字段：`txid`/`outputIndex`/`satoshis`/`script` → web-wallet `UTXO{TxID, Index, Value, Script}` |
| `GET /fee` | `estimatefee` | ✅ |
| `GET /transaction/{hash}` | `getrawtransaction` | ✅ |
| `POST /broadcast {raw}` | `sendrawtransaction` | ✅ |
| `POST /construct`（代币层） | — | ❌ btcd 无代币层，仍走 TokenAPI |

### 3.3 返回结构差异（需小适配）

- `getaddressutxos`：`outputIndex`（web-wallet 用 `index`）、`satoshis`（web-wallet 用 `value`）——**字段名映射**即可
- `getaddressbalance`：用 `balance_spendable` + `balance_immature` 拼 `Balance{Confirmed, Unconfirmed}`；注意 -5 错误码（地址无记录）web-wallet 已按 0 处理，rpcclient 的 `RPCError` 同样含该码 ✅
- sugarindex 扩展方法 rpcclient **无内建封装**（仅核心方法有），需用 `client.RawRequest` 或自定义 `Future` 类型调用（btcd 官方模式）

### 3.4 依赖

- 需在 web-wallet `go.mod` 增加 `github.com/btcsuite/btcd/rpcclient/v2`（与 btcd v0.24.2 同源）✅
- 或直接复用已声明的 `btcd` 主模块路径（同仓库子包）

### 3.5 结论

**可以直连**。web-wallet 仅需 3 处改动：① 加 `rpcclient` 依赖；② 新建 `internal/api/rpc.go`（ConnConfig + sugarindex 方法封装，`RawRequest` 处理扩展方法）；③ 保留现有 REST 客户端为回退/兼容，或直接替换。代币层（TokenAPI）维持原状。

## 四、方案对比

### 方案 A：web-wallet 改用 rpcclient 直连（推荐）

| 项 | 说明 |
|----|------|
| 改动 | web-wallet 加依赖 + 新增 rpc 客户端（~150 行）；`SugarClient` 方法改调 rpcclient |
| 优点 | 无中间层、无认证配置外露（复用 btcd-runtime.ini 凭据）、延迟最低、调试最直接 |
| 缺点 | 改 web-wallet 代码；sugarindex 扩展方法需 `RawRequest` 封装 |
| 风险 | 低（btcd 官方库，认证/协议成熟） |

### 方案 B：ini-node 侧加薄 REST 网关（不动 web-wallet）

| 项 | 说明 |
|----|------|
| 改动 | 在 `sugarchain-node/backend` 新增一个小 HTTP 服务（如 `walletapi`），监听 `/balance /unspent /fee /transaction /broadcast`，内部调 btcd RPC（Basic Auth） |
| 优点 | web-wallet 零改动，只改配置 `SugarAPI=http://127.0.0.1:8334`；协议与现状一致 |
| 缺点 | 多一层进程/端口；需处理认证注入与错误码透传；代币层仍独立 |
| 风险 | 低-中 |

### 推荐

**先方案 A**（rpcclient 直连，最干净）；若希望 web-wallet 完全不动、只改配置，则方案 B。
