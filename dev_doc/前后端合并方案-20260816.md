# 前后端合并方案：RPC 功能独立 + 非 RPC 控制中心页面

> 制定日期：2026-08-16
> 背景：节点已具备孤儿判定修复、快照秒级启动、加载/重建进度、subver=ini；`txindex=1` 已开启（单线程重建中）。
> 目标：RPC 相关网页功能独立；非 RPC 功能集成到一个**控制中心页面**（钱包未运行 RPC 服务时也显示），涵盖后端启停、启动参数（带说明）、日志控制、数据库参数（不重建的、默认当前调优值）、当前状态与进度。

---

## 一、架构总览：两页面体系

```
前端（单入口 SPA）
├── RPC 功能页面（钱包核心）           ← 依赖 RPC 8334
│     ├── Dashboard（余额/同步状态/进度条）
│     ├── 转账 / 交易 / UTXO / 地址
│     └── 设置（Backend 选择 REST/RPC 等）
│
└── 控制中心页面（非 RPC）              ← 不依赖 RPC，节点未运行也显示 ★新增
      ├── 后端启停
      ├── 启动参数（带说明）
      ├── 日志控制
      ├── 数据库参数（修改不重建）
      └── 当前状态 / 进度 / ETA
```

**关键**：RPC 页面在 `RPC 不可用` 时自动跳转/引导到控制中心页面（节点未启动场景）；控制中心页面通过**独立于 RPC 的本地通道**工作（读写 ini、控制进程、读日志/进度文件），不依赖 btcd RPC。

## 二、控制中心页面（非 RPC）详细设计

### 2.1 后端启停设置
| 控件 | 功能 | 实现 |
|------|------|------|
| 启动按钮 | 拉起 btcd（探测 8334 防双开） | 复用 BackendHost（子进程）或 schtasks `btcd-node` |
| 停止按钮 | 优雅停节点 | OnShutdown 清理；PowerShell Stop-Process |
| 状态灯 | 运行中/停止/启动中 | 轮询 8334 + 进程检测 |
| 自启动开关 | 是否随钱包启动自动拉起 | 持久化到前端配置 |

### 2.2 启动参数设置（每个字段带说明）
以 `btcd-runtime.ini` 为准，表单化展示，**每项含中文说明**：
| 参数 | 说明 | 当前值 |
|------|------|--------|
| `datadir` | 数据目录（区块+索引） | `C:\Users\adest\AppData\Local\Btcd` |
| `rpclisten` | RPC 监听地址 | `127.0.0.1:8334` |
| `rpcuser`/`rpcpass` | RPC 认证 | `sugar`/`sugar` |
| `headerwindow` | 内存头窗口（块数） | `50000` |
| `txindex` | 交易索引（getrawtransaction 可用） | `1`（重建中） |
| `sugarindex` | 地址/花费/时间戳索引（umami 兼容） | `1` |
| `addcheckpoint` | 信任检查点（加速启动） | `43760164:...` |
| `notls`/`upnp`/`profile` | 传输与调试 | `1`/`1`/`6000` |

修改原则：**级别 B（改 ini + 重启，不重建）** 的参数可直接改；**级别 C（需重建）** 参数改后弹双重确认（输入 REBUILD 关键字）。

### 2.3 日志控制
| 控件 | 功能 |
|------|------|
| 日志级别 | 各子系统（CHAN/INDX/SRVR/BCDB 等）独立设 debug/info/warn/error |
| 实时查看 | 尾随读取 `logs/node.stdout.log`（WebSocket/轮询） |
| 下载日志 | 导出当前日志文件 |
| 清空/轮转 | 清空或归档当前日志 |

### 2.4 数据库参数（修改**不会重建**，默认=当前调优值）
直接映射到已调优的运行时参数，全部为**级别 B（不重建）**或更低风险项：
| 参数 | 当前调优值 | 说明 |
|------|------------|------|
| `WriteBuffer` | 64 MiB | leveldb 写缓冲（sugarindex） |
| `TableSize` | 64 MiB | leveldb SSTable 大小 |
| `CompactionTotalSize` | 256 MiB | 压缩总预算（写放大治理） |
| L0 文件数 | 8 | leveldb L0 触发阈值 |
| `rebuildReadWorkers` | 4 | 索引重建读并行 worker |
| `fetchBatchBlocks` | 128 | 批量读 spend journal 块数/批 |
| `rebuildBatchBlocks` | 100 | 批量写块数/批 |
| `headerwindow` | 50000 | 内存头窗口（与启动参数联动） |

> 设计原则：**默认值 = 当前调优运行的参数**；这些参数修改**不需要重建数据库**，重启后生效（级别 B）；界面标注"修改不重建，重启生效"。

### 2.5 当前在干什么 + 进度（状态机）
统一状态机，读取独立进度文件（非 RPC）：
```
状态: 空闲 | 加载区块索引 | 重建索引(phase=load/index) | 同步区块 | txindex 重建
进度: 统一 progress.json（height/total/percent/updatedAt）+ ETA
```
- 复用现有 `/api/index-progress`（读 `datadir/index/progress.json`，含 phase）
- 增加 `phase=txindex`（txindex 重建进度，后台单线程，可加计时/进度）
- 同步进度：复用 Dashboard 的同步 ribbon
- 展示：大状态卡片 + 进度条 + ETA（基于两次轮询速率）

## 三、RPC 功能独立设计

1. **RPC 页面组件**（Dashboard/转账/交易/UTXO/设置）全部依赖 `Services`（REST 或 rpcclient），**互不依赖控制中心**
2. **RPC 不可用检测**：轮询 `/rpc` 或 8334 探活；失败 → 顶部横幅 + 自动引导"打开控制中心"（或跳转）
3. **控制中心不依赖 RPC**：启停/参数/日志/进度全部走独立通道（文件 + 进程控制），RPC 挂掉也不影响
4. **单入口**：BackendHost（子进程管理，探测 8334 防双开）拉起节点；前端首屏判断 RPC 是否可用 → 可用进 RPC 页面，否则进控制中心

## 四、实施路线（分阶段）

| 阶段 | 内容 |
|------|------|
| **P0** | 现有：RPC 页面可用、`/api/index-progress`（load/index phase）已就绪 |
| **P1** | BackendHost：前端自动拉起/停止 btcd（复用 `前后端整合完善方案` 的 P1） |
| **P2** | 控制中心骨架：启停 + 状态/进度卡片（读取 progress.json + 进程检测） |
| **P3** | 启动参数表单（带说明，级别 B/C 双重确认）+ 保存到 ini |
| **P4** | 日志控制（级别/查看/下载/清空） |
| **P5** | 数据库参数表单（默认=当前调优值，标注"修改不重建"）+ 前端路由分流（RPC 可用/不可用） |
| **P6** | txindex 并行优化（若单线程重建太慢，实施任务11 设计的读并行+写串行） |

## 五、风险与边界

| 风险 | 缓解 |
|------|------|
| 控制中心误改参数导致节点起不来 | 参数校验 + 保存前备份 ini + 恢复按钮 |
| 启停失控 | 状态机幂等（启动探测 8334、停止用 OnShutdown） |
| 级别 C 参数误操作全量重建 | 双重确认（弹窗 + REBUILD 关键字）+ 默认隐藏 |
| 日志查看性能 | 尾随读取 + 按行分页，不整文件加载 |
| 数据库参数改错 | 全部级别 B（不重建）+ 标注当前调优默认值 |
