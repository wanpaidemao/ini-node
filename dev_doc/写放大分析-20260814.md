# UTXO Flush 写侧开销日志分析（埋点统计）

> 生成日期：2026-08-14
> 数据来源：`backend/logs/node.stdout.log`（埋点日志 `UTXOC:` / `DBF:`）
> 节点状态：已追平链尖（IBD 完成），处于稳态监听

---

## 一、背景与目标

节点每约 5 分钟出现一次持续 40 秒、峰值 ~55 MB/s 的磁盘写入尖峰（见 `dev_doc/问题.md` 关联分析）。为量化"写这一侧开销到底花在哪"，在两条关键路径加埋点：

| 埋点 | 位置 | 测量内容 |
|------|------|----------|
| `UTXOC:` | `blockchain/utxocache.go` `writeCache()` | 应用层：序列化 + 内存 treap 写入（UTXO 缓存 → dbCache），条目数/字节/耗时 |
| `DBF:` | `database/ffldb/dbcache.go` `flush()` | 落盘层：dbCache → leveldb 批量提交，拆分为 `syncBlocks`（块文件 fsync）与 `ldbCommit`（leveldb 事务提交，含 WAL + memtable），以及总耗时 |

## 三、各环节耗时占比

以 09:36:52 样本为例（单次 flush 总链路 = UTXOC 7.6ms + DBF 52.4ms ≈ **60 ms**）：

| 环节 | 耗时 | 占比 | 说明 |
|------|------|------|------|
| UTXOC（应用层序列化+内存） | 7.6 ms | ~13% | 纯内存操作，非瓶颈 |
| DBF syncBlocks（块文件 fsync） | 0.6 ms | ~1% | 稳态下无新块文件，近乎零 |
| DBF ldbCommit（leveldb 提交） | 51.9 ms | **~86%** | 唯一接近磁盘的部分：WAL + memtable |

**关键结论**：同步路径（应用层 → dbCache → leveldb 提交）总耗时仅 ~60 ms，**远不足以解释 40 秒尖峰**。观测到的 40 秒持续 IO 必然来自 ldbCommit 之后由 leveldb **异步触发**的 compaction（L0→L1→L2 后台合并），而非同步 flush 本身。本次埋点证实：写放大开销在 compaction 阶段，`ldbCommit` 只是把数据写进 memtable/WAL 的前置成本。

---

## 四、写放大估算（含样本局限性）

- 09:36:52 样本：逻辑写入 1.40 MiB（DBF 字节）→ ldbCommit 51.9 ms。
- 若按之前观测的 98 MiB IBD 大 flush + 40 s × 55 MB/s ≈ 2.2 GB 实际落盘推算，**写放大 ≈ 2.2 GB / 98 MiB ≈ 22 倍**（LSM 随机 key 的典型范围 10–30x，吻合）。
- **局限**：当前节点已追平链尖，两次采样均为**稳态小 flush**（数百 KiB ~ 1.4 MiB），不包含 IBD 期间 98 MiB 大 flush 的完整采样。要量化 compaction 阶段的实际写放大，需在**追块（IBD）期间**采集 `typeperf` IO 与 `DBF:` 日志对照。

---

## 五、结论与建议

1. **写侧开销分层清晰**：应用层 ~8ms、leveldb 提交 ~52ms（均为毫秒级），40 秒尖峰几乎全部来自 **leveldb 后台 compaction 的写放大**（随机 sha256 key 导致近似全表重写）。
2. **治理优先级不变**：
   - 治本（降总写量）：调大 `defaultCompactionTotalSize` 128→256-512 MiB、`defaultWriteBuffer` 32→64-128 MiB（`database/ffldb/db.go` 常量）；
   - 治感知（摊平尖峰）：应用层分批/节流 flush（`utxocache.writeCache` 拆小事务）。
3. **埋点保留价值**：`UTXOC:` / `DBF:` 常驻日志可随时量化任意时段的 flush 开销；本分析可直接复用。

---

## 六、再次采集方法

```bash
# 1) IBD 追块期间观察（需重启节点或等待下次追块）
typeperf "\Process(btcd)\IO Data Bytes/sec" -si 10 -sc 60   # 跨 flush 周期采样

# 2) 对照埋点日志
grep -E "UTXOC:|DBF:" logs/node.stdout.log | tail -20

# 3) 统计各环节耗时
grep "DBF:" logs/node.stdout.log | awk '{print $NF}'        # total 列
```

> 建议：下一次节点重启进入 IBD 时重复采集一轮，即可补齐 98 MiB 大 flush 的 compaction 写放大完整数据。
