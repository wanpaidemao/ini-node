# btcd 上游同步与迁移方案 v3（最终版）/ Upstream btcd Sync & Migration Plan v3 (Final)

> 更新日期：2026-08-29
> 决策链：v1（fork+merge）→ v2（分叉面收敛+按需同步）→ override 注入点设计 → **v3 简化主方案（最终）**
> 对比基准：fork 最新 vs 上游 btcd master（v0.26.2，快照于 d:\dev\AI\btcd-ref）

## 一、最终决策 / Final Decision

**主方案 = 保留全部本地硬代码 + patch-queue 补丁化管理 + 1-2 年一次上游同步。**

- **必须保留**：所有好不容易写出来的硬代码（并行同步、header 窗口、冷读、存储优化、sugarindex、共识差异等）**一律保留**，不做"压回上游/重同步"。
- **同步节奏**：btcd 不需要频繁跟进，**每 1-2 年合并一次**上游 tag 即可。
- **不再做大范围共识重构**：override 注入点架构（v3 前设计）因"1-2 年才痛一次"而**降级为备选**，
  仅在某次上游大改导致冲突爆炸时才针对性启用（详见 §六）。
- **低成本动作随时做**：子模块依赖升级（改 go.mod）、紧急安全/共识修复单独 cherry-pick、
  通用补丁提上游 PR。

## 二、耦合度事实（量化依据）/ Coupling Facts

- 这是 **btcd 完整 fork**：主模块声明即 `github.com/btcsuite/btcd`。
- 3433 个共同文件中 **54 个被修改**（1.6%），fork 新增 62 个文件。
- 被改行数 ≈ **9,000 行**（含测试），集中在：同步（netsync +2700）、存储（chainio +1017）、
  链视图（chain +695）、窗口（blockindex +506）、共识（difficulty/validate/merkle/process 等 ~800）、
  装配/RPC（server/config/btcd/rpcserver 等 ~800）。
- 关键事实：主节点二进制**只编译「主模块 + replace 的 chaincfg/txscript」**；
  wire/btcec/btcutil/v2transport/address 用的是**模块缓存上游原版**（go.mod 固定版本），
  仓库里同名子模块是"休眠 fork"（主程序不用）。
- 完全未修改（零冲突区）：`mempool/`、`peer/`、`connmgr/`、`addrmgr/`、`scriptval` 及子模块。

## 四、1-2 年同步流程 / Sync Workflow

### 4.1 准备（一次性）
```bash
git remote add btcd https://github.com/btcsuite/btcd.git
git fetch btcd
```

### 4.2 年度合并
```bash
git merge btcd/<tag>              # 1-2 年一次，合并上游 tag
git apply patch/01-*.patch ...    # 重放本地补丁，冲突定位到补丁级
# 手工解决冲突 → 逐补丁确认语义 → 回归
```

### 4.3 回归验收
编译、单测、主网全量同步（高度对齐无分叉）、与 umami 共识对拍、sugarindex 一致性、挖矿回归。

### 4.4 非年度轻量动作
- 依赖升级：改 `backend/go.mod` 版本号 + `go mod tidy`（随时可做）
- 紧急修复：上游关键安全/共识修复单独 cherry-pick
- 通用补丁提 PR：utxocache 残留清理、ffldb 调参等，进上游即零维护

## 六、备选方案（保留待用）/ Backup Plan

**override 注入点架构**（详见 `dev_doc/btcd共识override注入点设计-20260829.md`）：
仅在以下情况启用——
- 某次上游大改导致冲突爆炸、patch-queue 解不动；
- 或未来同步需求变频繁（如每年多次）时，再对最痛点（难度）做局部钩子化。

当前**不主动实施**，避免共识重构引入共识 bug 的风险。
