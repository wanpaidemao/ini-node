# 开发流程与代码提交规范 / Dev Process & Commit Standards

> 更新日期：2026-08-29
> 适用范围：ini-node 全仓库（backend + frontend + dev_doc）
> 原则：**先设计后实现、分步完成、全程留痕、提交规范化**

---

## 一、开发总流程 / Development Workflow

每个功能/修复按以下顺序推进（每步留痕）：

1. **读文档**：先读仓库根目录 `README.md`、`dev_doc/` 下相关 md、`backend/doc/md/` 下相关文档，
   了解现状与既有约定，避免重复造轮子。
2. **设计界面（UI 先行）**：凡涉及界面（frontend / 工具 CLI / 面板），先设计美观可用的界面，
   再进入技术方案。
3. **设计方案**：产出技术方案（改动点、影响面、风险），方案较大的写入 `dev_doc/` 新文档。
4. **分步实现**：把方案拆成小步骤，一次一个步骤，每步可独立编译/回归/回退。
5. **记录进度**：每个步骤完成 → 更新 `dev_doc/待办/待办.md`（任务状态）与对应方案文档，
   并在提交信息中标注步骤编号。

> 硬性要求：**不许"一把梭"**。大改动必须分步、每步有产出、有提交、有记录。

### 代码修改流程（Checklist）——每次改代码按此走

- [ ] **1. 读现状**：先读相关 `dev_doc/`、`backend/doc/md/` 文档与对应代码，确认现状，避免重复造轮子
- [ ] **2. 出方案**：明确改动点 / 影响面 / 风险；大改动先写 `dev_doc/` 方案文档
- [ ] **3. 分步实现**：把改动拆小步骤，一步一提交，每步可独立编译
- [ ] **4. 双语注释**：新增/改动代码加**中文+英文**双语注释
- [ ] **5. 质量门禁**：`gofmt -l .` 无告警、`go vet ./...` 通过、相关 `go test` 全绿
- [ ] **6. 同步文档（防过时）**：若改动影响了 `backend/doc/md/` 或 `dev_doc/` 里引用的**行号 / 参数 / 状态 / RPC**，**同步更新并标注核对日期**（文档头部加"核对状态"行）
- [ ] **7. 记录进度**：更新 `dev_doc/待办/待办.md` 任务状态
- [ ] **8. 提交**：按 §三 提交规范（`[版本号-步骤]` 双语），用 `git add <file>` 精确暂存
- [ ] **9. 推送前自查**：`git status` 无意外文件、`git log --oneline -3` 信息合规

## 二、代码规范 / Code Standards

1. **编码 UTF-8**：所有源码/文档使用 UTF-8（无 BOM）。
2. **双语注释**：修改/新增代码时，注释用 **中文 + 英文** 双语（先中文再英文，或同行双写）。
3. **依赖不落 C 盘**：构建/测试时设置模块缓存到 D 盘：
   ```powershell
   $env:GOMODCACHE='D:\codeX\gomodcache'
   ```
   （仓库 Go 版本要求：`backend/go.mod` 为 go 1.25.0）
4. **代码格式**：Go 代码 `gofmt -l .` 无告警、`go vet ./...` 通过后再提交。
5. **不改无关键逻辑**：除非必要，不做超出任务范围的"顺手重构"。

## 三、代码提交规范 / Commit Standards

### 3.1 提交信息格式

```
[项目版本号-拆分步骤编号] <type>: <英文摘要> / <中文摘要>

- <要点 1> / <英文要点 1>
- <要点 2> / <英文要点 2>
```

- **项目版本号**：取 `backend/version.go` 的 `appMajor.appMinor.appPatch`（当前 **0.0.1**）。
- **拆分步骤编号**：按本次开发拆分步骤递增（如 `0.0.1-1`、`0.0.1-2`…）。
- **type**：遵循常规语义（`feat` / `fix` / `docs` / `refactor` / `perf` / `test` / `chore`）。
- **双语**：摘要与要点均为 **英文 + 中文**。

### 3.2 示例

```
[0.0.1-4] docs: add dev process & commit standards / 新增开发流程与提交规范
- 定义分步开发流程与进度留痕 / stepwise workflow with progress logging
- 规定 commit 格式与双语要求 / commit format and bilingual rule
```

### 3.3 提交纪律

1. **按需提交**：功能完成一个步骤即提交一次，不做"大杂烩提交"。
2. **精确暂存**：按文件名 `git add <file>` 精确暂存，**禁止** `git add .` / `-A` 误带无关文件。
3. **不提交敏感文件**：`.env`、密钥、证书、大数据文件一律不进版本库。
4. **推送前自查**：`git status` 确认无意外文件；`git log --oneline -3` 确认提交信息符合格式。

## 四、btcd 上游同步流程 / Upstream Sync（1-2 年一次）

> 决策（2026-08-29）：**简化主方案**——保留全部本地硬代码，不做大规模共识重构。
> 详见 `dev_doc/btcd上游同步迁移方案-20260829.md`。

### 4.1 准备工作（一次性）

```bash
# 挂上游 remote
git remote add btcd https://github.com/btcsuite/btcd.git
git fetch btcd
```

### 4.2 patch-queue 补丁管理（核心）

把每块本地硬代码抽成独立补丁，永久保留：

```
patch/
├── 01-consensus-difficulty.patch      # 难度算法（SugarShield-N510）
├── 02-consensus-timewindow.patch      # 未来时间窗 60s
├── 03-consensus-witness.patch         # 无 coinbase witness commitment
├── 04-consensus-miner-block.patch     # 矿工块上链判定
├── 10-sync-parallel.patch             # 并行 header/block 同步
├── 11-storage-header-window.patch     # header 窗口/冷读（chainio）
└── 20-assembly-rpc.patch              # 装配/RPC 扩展
```

生成方式（示例）：
```bash
git diff <上游基线> HEAD -- backend/blockchain/difficulty.go > patch/01-consensus-difficulty.patch
```

### 4.3 年度同步步骤

```bash
git fetch btcd
git merge btcd/<tag>               # 每 1-2 年合并一次上游 tag
git apply patch/01-*.patch ...     # 逐个重放补丁，冲突定位到补丁级
# 手工解决冲突 → 逐补丁确认语义 → 编译 → 回归
```

### 4.4 回归验收（每次同步后必做）

- `go build ./...`（backend）编译通过
- `go test ./...`（重点 blockchain / netsync / wire / sugarindex）全绿
- 主网全量同步：高度与网络一致、无分叉
- 共识对拍：与 umami 高度/难度对齐
- sugarindex 索引一致性；挖矿/出块正常

### 4.5 非年度节奏的轻量动作

- **依赖升级**：wire/btcec/btcutil 等子模块版本号随时可升（改 `backend/go.mod` + `go mod tidy`），
  不绑定代码合并周期。
- **紧急修复**：订阅上游公告；遇到关键安全/共识修复**单独 cherry-pick**，不等年度同步。
- **通用补丁提 PR**：把通用 bug 修复/性能参数（如 utxocache 残留清理、ffldb 调参）
  提交到 btcd 上游——进上游的代码永远零维护。

## 五、回归与质量门禁 / Quality Gates

| 项 | 命令 | 通过标准 |
|----|------|---------|
| 格式 | `gofmt -l .`（backend） | 无输出 |
| 静态检查 | `go vet ./...` | 无错误 |
| 单测 | `go test ./...`（backend） | 全绿 |
| 编译 | `go build ./...` | 通过 |
| 同步回归 | 主网全量同步 | 高度对齐、无分叉 |
| 文档留痕 | `dev_doc/待办/待办.md` 更新 | 任务状态最新 |
