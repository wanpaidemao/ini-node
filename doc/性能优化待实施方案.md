## 二、每项详情

### 2.1 A3 写盘队列（轨道，最高风险）
- **目标**：把链写锁内的"ffldb 块体 + 单事务元数据 + UTXO flush"写盘路径拆出为独立 writer，元数据 N 块合并为一次写事务，高度水印可重放。
- **收益机制**：写事务数 ÷N，写盘期链锁占用消失，`getblockchaininfo`/`getblocksyncstatus` 全程 <1s。
- **失效模式**：四线一致错位（状态/UTXO/索引/水印），崩溃重启需重建或丢状态（同型 P8/P9）。
- **依赖**：A2 边界（需知道哪些数据在哪个锁域）。
- **实施要点**：
  - 写盘数据按 `(blockHeight, blockData, utxoDiff, indexBatch)` 打包入队；
  - 独立 writer goroutine 串行落盘，成功后推进水印；
  - 重启时从水印重放未落盘块（可考虑引入 WAL 或复用 blocks_ffldb 的 metadata batch）。
- **验证**：kill -9 随机高度 ×100 后重启，四线断言一致；写事务数下降 ≥50% 有数据。

### 2.2 A2 链锁分域（轨道）
- **目标**：把单一的 `trackedRWMutex` 链锁拆成回滚/连接/查询三个分域锁，跨域只读不互斥。
- **收益机制**：锁等待近零，blockHandler 几乎不排队。
- **失效模式**：跨域 race——回滚（写 4 个域）与并发查询（读各域）联动漏审。
- **依赖**：A1 锁外校验边界（脚本校验依赖 tip 视图），A4 预取版本绑定。
- **验证**：`go test -race` + 人工构造分叉/孤儿洪流/竞争失败自愈回归。

### 2.3 A4-3 UTXO 分层预取与分代 flush（轨道）
- **目标**：在 A4-1（增量 flush）/A4-2（脏集合追踪）之上，加 UTXO 热区（内存驻留）/预取队列（前瞻 N 块）/冷区（DB），分代 flush 减少读放大。
- **收益机制**：缓存删除命中率↑、DB 读放大↓。
- **失效模式**：预取版本与链视图绑定错→旧视图被应用（需重校验/丢弃）。
- **验证**：同步 + 回滚回归；A6 基线对比 read 次数/命中率。

### 2.4 F4 Explorer 分页 / 懒加载（P2 体验）
- **内容**：Explorer 页 getblock/getrawtransaction 改为分页或滚动懒加载，避免一次拉整条链。
- **验收**：长区块页首屏可交互。

### 2.5 F5 图表 / peer 表虚拟滚动（P2 体验）
- **内容**：Internals 页图表与 peer 表大数据量虚拟化。
- **验收**：万级节点下滚动不掉帧。

### 2.6 F6 余额 / UTXO 批量查询（L4）
- **内容**：`gatherUTXOs`/`nodeUTXOsAll` 从逐地址 RPC 改为批量（一次 RPC 传多地址，或节点端批量接口）。
- **验收**：多地址钱包余额加载时长明显下降。

### 2.7 O6 lead 放宽（横切，低风险）
- **内容**：`headerLeadLimit` 42000 → ≤57000（上限 58000，余量 ≥1000）。**前提**：O2 请求窗口缓存已落地（本次实现），放宽后接收端 prev 校验不会再逐高度 DB 冷读。
- **收益**：仅增韧性不提速（回退重下段的余量更大）。
- **验证**：回退重下段速度 = 正常段（A6 冷读计数为 0）。

### 2.8 A7 日志异步（L3，低风险）
- **内容**：日志写入改为异步 writer（有界队列 + 后台落盘），链锁内零日志 I/O。
- **失效模式**：崩溃丢尾部日志（可接受）。
- **验证**：锁内日志路径移除；性能前后对比。

### 2.9 F8 Wails time 事件降频（L1）
- **内容**：`main.go` 每 1s `Emit` 的 time 事件改为降频（如 2-5s）或页面可见性门控。
- **验收**：事件每秒发送次数下降，页面无感。

### 2.10 F9 打包瘦身（L1）
- **内容**：vite tree-shake、i18n 资源瘦身（frontend/dist 内嵌体积）。
- **验收**：产物体积、首屏资源数下降。

### 2.11 F10 启动解耦（L3）
- **内容**：Wails 窗口创建与节点启动解耦：节点后台启动 + 窗口就绪轮询，避免启动阶段 UI 卡死。
- **验收**：冷启动窗口立即出现，节点就绪横幅过渡平滑。

### 2.12 O8 冷读埋点（横切，低风险）
- **内容**：把 A6 的冷读命中/驱逐计数（coldCache hit/refresh、window evict 计数）暴露到 `getblocksyncstatus`。
- **验收**：Internals 页可直接观察冷读是否归零（O2 生效证据）。

## 三、推进建议

1. **先验证 O2（本次改动）**：跑节点观察回退重下段速度；确认无回归后本地提交 → 用户验证 → push 远程。
2. **随后做低风险横切**：O6（依赖 O2 已就位）、A7、O8——三者独立可提交，收益即时可见。
3. **前端体验（P2）**：F4/F5/F6/F8/F9/F10，任选推进，风险低。
4. **轨道大改（A3/A2/A4-3）**：单独评审、单独回退；严格按"每刀有 A6 基线佐证 + 人工分叉/孤儿洪流/竞争失败自愈回归 + kill -9 随机点一致性"验收，不得跳序（依赖链 A6→A5→A4→A3→A2，A4-3 需在 A3/A2 前安全落定）。

## 四、验收指标（总计，来自总方案）

1. 写盘期 `getblocksyncstatus` < 1s，前端无超时（G1）。
2. IBD 无 >10s 零速段；回退重下段不冷读（G2）。
3. 删库全量重同步 ≤ 8h（G3）。
4. 日志 ≤ 数百 MB；写事务数下降 ≥50% 有数据（G4）。
5. RSS 有界（G5）。
6. 全部优化有 A6 基线佐证，无"凭感觉变快"（G6）。
