## 二、已完成项（2026-09-10 落地的 O/F 系列）

> 以下各项在本轮已实现并推送（提交线 `eafd7406`→`bb9ef6d3`→`cd4066d6`→`e4359abd`→`71888533`）。

### 2.1 O2 请求窗口 hash 缓存（已完成）
- **内容**：`headerLocator` 与两处 prev 校验（handleParallelHeadersMsg / applyHeaderRange）先查 `requestWindowCache`，miss 回填，消除回退重下段对已逐出窗口高度的 DB 冷读。
- **修复**：普通 REORGANIZE 时 `NTBlockDisconnected` 通知也清空缓存（`bb9ef6d3`），避免重组后残留过期 hash 导致误判 fabricated 链回滚、SYNC 停死。
- **验证**：日志确认普通 reorg 后同步持续恢复推进，无停死。

### 2.2 O6 lead 收紧（已完成，方向修正）
- **内容**：`headerLeadLimit` 42000→**10000**（原方案为放宽至 57000，分析后方向反转：放大 lead 逼近窗口 50000 反而引入冷读边界）。lead 远小于窗口 → 接收端 prev 校验**永远内存命中**，零冷读。
- **配套**：`defaultBlockSyncStartLead` 20000→8000（否则 lead cap 先于并行块下载启动暂停派发，IBD 退化为串行）；O2 缓存容量随 lead 缩至 ~12000 条。

### 2.3 A7 日志异步（已完成）
- **内容**：`logWriter` 改为有界队列（8192）+ 后台 flush goroutine，持链锁的日志调用只入队不做文件 I/O；关闭时先排空队列再关 rotator；`stopped` 原子标志 + `Dropped()` 计数 + `logRotatorMu` 保护消除关闭/初始化竞态。

### 2.4 O8 冷读埋点（已完成）
- **内容**：`HeaderHashByHeight` 双路径原子计数（窗口命中 / DB 冷读），经 `getblocksyncstatus`→`SyncStatus`→Internals A6 卡片暴露（"header 窗口 N · 冷读 M"），覆盖所有调用方（prev 校验、locator、完成循环）。

### 2.5 F8 time 事件清理（已完成）
- **内容**：删除 `main.go` 每秒 `Emit("time")` 死事件（前端从未监听，无任何 `Events.On("time")`）+ `RegisterEvent` 声明 + 过时注释 + 重新生成的 bindings。

### 2.6 F10 启动解耦（已完成）
- **内容**：ControlCenter 挂载时尊重 `runnodeonstart` 自动拉起节点（异步 `cmd.Start` 不阻塞窗口，rpclisten 探测幂等）；**双开修复**：`handleNodeStart` 增加 `nodeProcessRunning()`（tasklist/pgrep）第二道防线，消除"DB 加载中 RPC 未就绪"窗口期的双开冲突（曾致 :6000/数据文件占用 ERR）。

### 2.7 F4 / F6 确认已实现（无需改动）
- **F4**：Explorer 列表封顶（默认 12 块）+ `Promise.all` 并行取 hash/头（原 24 次串行 RPC）+ 可配置数量，不做全链拉取。
- **F6**：`nodeUTXOs(addrs)` 一次 `getaddressutxos` 批量 RPC 传整个地址数组，`gatherUTXOs` 直接复用；逐地址循环仅存于外部 REST 降级路径（协议限制，仅作兜底）。

## 四、验收指标（总计，来自总方案）

1. 写盘期 `getblocksyncstatus` < 1s，前端无超时（G1）。
2. IBD 无 >10s 零速段；回退重下段不冷读（G2）。
3. 删库全量重同步 ≤ 8h（G3）。
4. 日志 ≤ 数百 MB；写事务数下降 ≥50% 有数据（G4）。
5. RSS 有界（G5）。
6. 全部优化有 A6 基线佐证，无"凭感觉变快"（G6）。
